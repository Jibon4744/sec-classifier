# SEC — Project Requirements (v1)

## Features list

1. **Disease-only mode** — upload one leaf image, get disease classification.
2. **Growth-stage-only mode** — upload one flower/plant image, get growth-stage
   classification.
3. **Combined mode** — upload both a leaf image and a flower/plant image, get
   both classifications PLUS an LLM-generated analysis of whether the apparent
   growth stage is genuinely age-related or distorted by the detected disease.

Only mode 3 calls an LLM. Modes 1 and 2 are fully deterministic — ensemble
prediction + a static lookup table, no LLM involved, no per-call cost, no
latency from an external API.

## API design — 3 endpoints (clean separation, matches your 3 UI options)

### POST /predict/disease
**Input**: multipart form, field `leaf_image` (jpg/png)
**Process**: run the 4-model ensemble on the leaf image only.
**Output**:
```json
{
  "mode": "disease",
  "predicted_class": "Alternaria leaf spot",
  "confidence": 0.8961,
  "per_model_breakdown": {
    "mobilenet": "Alternaria leaf spot",
    "resnet50": "Alternaria leaf spot",
    "efficientnetv2s": "Downy Mildew",
    "vgg16": "Alternaria leaf spot"
  },
  "info": {
    "cause": "Fungal, spreads in humid/wet conditions",
    "treatment": "Apply fungicide, improve air circulation, remove infected leaves",
    "severity": "moderate"
  }
}
```
`info` comes from a static JSON lookup table you author (`disease_info.json`),
keyed by class name — NOT generated by an LLM. Source the actual content from
your thesis references so it's factually grounded, not invented.

### POST /predict/growth-stage
**Input**: multipart form, field `flower_image` (jpg/png)
**Process**: run the 4-model ensemble on the flower/plant image only.
**Output**:
```json
{
  "mode": "growth_stage",
  "predicted_class": "Full Bloom",
  "confidence": 0.912,
  "per_model_breakdown": { "...": "..." },
  "info": {
    "description": "Flower head fully open, petals extended",
    "typical_days_to_harvest": "20-25 days from this stage"
  }
}
```
Same rule: `info` from a static `growth_stage_info.json` lookup table, sourced
from real agronomic references — not LLM-generated.

### POST /predict/combined
**Input**: multipart form, fields `leaf_image` AND `flower_image` (both required)
**Process**:
1. Run disease ensemble on `leaf_image`.
2. Run growth-stage ensemble on `flower_image`.
3. Pass both results (class + confidence only, not raw images) to the LLM with
   a structured prompt (see below).
**Output**:
```json
{
  "mode": "combined",
  "disease": { "predicted_class": "Alternaria leaf spot", "confidence": 0.8961 },
  "growth_stage": { "predicted_class": "Wilted", "confidence": 0.91 },
  "llm_analysis": {
    "stage_appearance_reliable": false,
    "explanation": "The plant shows Wilted-stage appearance, but Alternaria leaf spot was also detected. This disease impairs photosynthesis and can cause premature wilting/aging that mimics natural late-stage maturity, independent of actual seed development time.",
    "recommendation": "Treat the disease first (see disease info). Re-assess growth stage in 1-2 weeks after treatment, since current appearance may not reflect true harvest timing."
  }
}
```

## LLM layer — scope and prompt design (mode 3 only)

**What the LLM receives**: only the two classification results (class names +
confidence scores) — never raw images, never asked to classify anything itself.
Its job is reasoning/explanation over already-computed facts, not prediction.

**System/task prompt (draft)**:
```
You are analyzing a sunflower health report. You are given:
- A detected leaf disease (or "none" if no disease detected): {disease_class}, confidence {disease_confidence}
- A detected growth stage: {growth_stage_class}, confidence {growth_stage_confidence}

Some growth stages (e.g. Wilted, Mature Bud) can visually resemble natural
late-stage maturity OR premature aging caused by disease stress (which impairs
photosynthesis). Your task:
1. State whether the current growth-stage appearance is likely a RELIABLE
   indicator of true plant age/harvest timing, or possibly DISTORTED by the
   detected disease.
2. Briefly explain your reasoning in plain language.
3. Give one practical recommendation.

Do not invent specific day-counts or scientific facts not implied by the input.
If disease is "none", simply confirm the growth stage reading is reliable and
skip the distortion analysis.

Respond in this JSON shape: {"stage_appearance_reliable": bool, "explanation": str, "recommendation": str}
```

This keeps the LLM's role narrow and grounded — reasoning over two facts you
already computed, not generating new facts from its own memory. That's the
defensible design point for interviews: the LLM explains and contextualizes,
it doesn't predict or fabricate numbers.
